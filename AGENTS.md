# AutoSci Codex Adapter

This repository is upstreamed as a Claude Code project, but it is also set up
for Codex. Keep the upstream `.claude/skills` directory as the source of truth
and use `.agents/skills` as Codex wrappers generated by
`tools/sync_codex_skills.py`.

## Running AutoSci Skills In Codex

- When the user invokes an AutoSci slash command such as `/init`, `/ingest`,
  `/ideate`, `/research`, or `/paper-draft`, use the same-named Codex skill
  from `.agents/skills`.
- When a selected wrapper points to `.claude/skills/<name>/SKILL.md`, read that
  upstream file completely and follow it as authoritative.
- Resolve references mentioned by an upstream skill relative to that upstream
  directory. For example, `references/foo.md` inside `/init` means
  `.claude/skills/init/references/foo.md`.
- Treat upstream references to "Claude Code" as the current Codex session unless
  they are specifically about Claude authentication, Claude-only CI, or the
  `.claude` settings file.
- Translate upstream `Skill: other-skill` and `/other-skill` handoffs into the
  matching repo Codex skill `$other-skill`.
- For upstream `Agent tool` instructions, use Codex subagents when available or
  parallel local tool calls when that is the narrower fit.
- For upstream `AskUserQuestion` gates, ask the user a concise question in the
  current Codex thread; use structured user-input tools only when available.
- For upstream `CronCreate` or scheduled monitoring instructions, use Codex
  automations when available; otherwise explain the manual monitoring command
  and leave the pipeline state explicit.

## Local Runtime

- Prefer `.venv/bin/python` on macOS/Linux or `.venv/Scripts/python.exe` on
  Windows for AutoSci tools. Fall back to `python3` or `python` only if the
  project virtualenv is missing.
- The local web UI is served with `python tools/serve.py` and defaults to
  `http://127.0.0.1:8765/`.
- Review LLM MCP is configured for Codex in `.codex/config.toml` and for Claude
  Code in `.mcp.json`. API keys still live in `.env`.

## Maintenance

- After running `./setup.sh --lang en` or `./setup.sh --lang zh`, run
  `.venv/bin/python tools/sync_codex_skills.py` if setup did not already do it.
- To check wrapper drift, run
  `.venv/bin/python tools/sync_codex_skills.py --check`.
